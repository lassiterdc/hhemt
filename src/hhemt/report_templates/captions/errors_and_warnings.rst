Validation report for **{{ snakemake.config.analysis_id }}** — surfaces the ``validation_report.json`` read-model written at consolidation by the same checks the pytest aggregate ``assert_analysis_workflow_completed_successfully`` runs. It is a projection, not a live re-check, and it does NOT render empty when that read-model is absent: it renders a green ``0 of 0 applicable checks passed`` banner. Read a zero denominator together with the omission line beneath it — no omission line means the read-model was missing or carried no checks; an omission line means every check was omitted as not applicable. Neither case means the analysis was clean. The page opens with that pass/fail banner, followed when applicable by that single count of omitted checks, then the structured failures in the order the page emits them: (1) system-level checks, (2) aggregate per-scenario checks, (3) resource-utilization mismatches (actual vs intended MPI / OMP / GPUs / GPU backend per scenario), and (4) granular per-scenario stage failures — which comes last because it applies no check of its own, re-presenting the detail rows of the checks above it.
